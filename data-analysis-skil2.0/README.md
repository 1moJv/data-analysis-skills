# 企业数据分析_四角色防幻觉-skill

一个基于 [Claude Code](https://claude.ai/claude-code) Skill 的**四角色分工企业级 AI 数据分析系统**。它把开源的 `data-analysis` 技能，从「多专家并行出报告」升级为「**防数值幻觉 + 结论可溯源**」的确定性分析流水线。

---

## What it produces（产出什么）

丢一个 CSV 进来，得到：

- **数据质量巡检报告** —— 缺失值 / 异常值（IQR）/ 重复行 / 常量列自动检测
- **指标 JSON** —— 由代码确定性计算的指标，作为「数字唯一事实源」
- **业务洞察结论** —— 受真实性边界控制的归因（L1 可验证 / L2 推断 / L3 截断）
- **复核校验报告** —— 代码层面二次校验（✅/❌），每个结论可溯源
- **离线可打开的交互式 HTML 报告** —— 内联 SVG 图表，断网也能完整打开

`sample-output/` 里是 36 个月 SaaS 数据跑通的真实产出（含 [企业数据分析报告_四角色防幻觉.html](sample-output/企业数据分析报告_四角色防幻觉.html)）。

## How it works（工作原理）

### 四角色串行流水线

```
① 数据探查 ──► ② 指标统计 ──► ③ 业务洞察 ──► ④ 复核校验 ──► 离线 HTML 报告
   (代码)        (代码)         (LLM + 边界)      (代码)          (代码)
```

核心理念：**数字来自代码，LLM 只做有边界的推理，结论必须可溯源。**

### 三道防幻觉防线（纵深防御）

| 防线 | 拦截的错误类型 | 机制 |
|---|---|---|
| ① 数据巡检 | 数据里的异常值 | IQR（1.5×IQR）离群检测 |
| ③ 真实性边界控制 | 无支撑的归因（缺维度强行下因果） | L1/L2/L3 分级 + 主动截断 |
| ④ 复核校验 | 数据内部矛盾 + 算错/编造的数字 | 6 项会计恒等式断言 + 独立重算比对 |

三道防线**各司其职、不可互相替代**，合起来才把「数值幻觉」和「脏数据」都挡住。

## 与原 data-analysis 技能的区别

| 维度 | 原 data-analysis 技能 | 本项目 |
|---|---|---|
| 架构 | 四阶段：数据理解→专家选择→并行分析→统一呈现 | 四角色串行流水线 + 独立复核 |
| 多 Agent 方式 | 并行视角：3–5 位领域专家各自做全量分析 | 任务解耦：每角色只做一件事 |
| 数字来源 | LLM「心算」，无人二次核对 | 代码确定性计算（pandas），LLM 不碰计算 |
| 防幻觉机制 | 无（鼓励「think one step ahead」主动归因） | 三道防线 |
| 复核校验 | 无 | 独立复核角色（重算 + 断言） |
| 归因边界 | 无约束，易强行归因 | L1/L2/L3 分级，数据不足主动截断 |
| 数据质量 | 手动 profile，无异常值检测 | 自动巡检（缺失/异常/重复/常量） |
| HTML 报告 | 依赖 ECharts CDN，需联网 | 离线可打开（内联 SVG + 内嵌数据） |
| 测试 | 无 | 内置回归测试（反例注入 + 自动断言） |

一句话：**原 skill 解决「分析得不够深、不够专业」；本项目解决「分析得不准、不敢信」。**

复用了原 skill 的：数据读取逻辑、9 种报告风格体系（视觉参考）、领域知识库（指标口径）、「结论先行」的报告写法。

## Usage（用法）

### 完整跑一次全链路

```bash
SK=".claude/skills/企业数据分析_四角色防幻觉/scripts"
OUT="sample-output"
DATA="sample-data/example.csv"

# ① 数据探查
python "$SK/数据巡检_缺失值与异常值检测.py" "$DATA" --out-json "$OUT/数据巡检报告.json"
# ② 指标统计
python "$SK/指标统计_确定性计算.py" "$DATA" --out-json "$OUT/指标统计结果.json"
# ③ 业务洞察（LLM 子代理，由 Claude 主流程驱动，输入指标JSON + 边界规则）
# ④ 复核校验
python "$SK/复核校验_代码二次校验.py" "$DATA" --stats-json "$OUT/指标统计结果.json" --out-json "$OUT/复核校验报告.json"
# ⑤ 报告合成
python "$SK/报告生成_离线交互HTML.py" --data "$DATA" --stats-json "$OUT/指标统计结果.json" \
    --insight-md "$OUT/业务洞察结论.md" --verify-md "$OUT/复核校验报告.md" --out "$OUT/企业数据分析报告.html"
```

> ③ 业务洞察是唯一允许 LLM 参与的环节，由 Claude 主流程以子代理方式驱动，并携带边界规则（`references/真实性边界控制_归因分级与截断规则.md`），因此未封装成命令行脚本。

### 换自己的数据

脚本是数据无关的，把 `$DATA` 换成你的 CSV 即可。若字段名不同，需在 `指标统计_确定性计算.py` 里做字段映射。

## Sample data（示例数据）

`sample-data/example.csv` 包含 36 个月（2022-01 ~ 2024-12）的 SaaS 经营数据，26 个字段：MRR/ARR、客户增减、流失率、NRR、收入/成本/毛利、三大费用、EBITDA、人效、CAC/LTV、客单价、扩张/收缩 MRR。是验证本技能分析深度与防幻觉机制的完整数据集。

## 反例验证与回归测试

一键注入反例 → 跑全链路 → 自动断言「应被拦截」：

```bash
python ".claude/skills/企业数据分析_四角色防幻觉/scripts/防幻觉回归测试_反例注入与自动断言.py"
```

| # | 用例 | 验证的防线 |
|---|---|---|
| 0 | 干净数据 → 复核不应误报 | 负对照 |
| 1 | 注入 MRR 异常值(10x) → 巡检检出 | ① 数据巡检 |
| 2 | 注入后 arr 未同步 → 复核检出 ARR=MRR×12 破坏 | ④ 一致性断言 |
| 3 | 篡改统计 JSON → 复核检出数字不一致 | ④ 独立重算 |

退出码 0 = 全部通过，1 = 有失败，可直接接 CI。

## Design principles（设计原则）

- **数字来自代码，LLM 只做有边界的推理** —— LLM 禁止心算，只能引用指标 JSON
- **结论必须可溯源** —— 每个数字都能回溯到「哪个文件、哪一行、公式」
- **数据不足就闭嘴** —— 宁可输出「数据不足，无法归因」，也不编造因果
- **复核不可信上游** —— 复核角色独立重算，不信任统计层的数字
- **报告可直接交付** —— 离线打开、图表内联、结论分级标注
