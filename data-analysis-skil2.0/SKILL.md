# 企业级 AI 数据分析（四角色防幻觉）

> 核心理念：**数字来自代码，LLM 只做有边界的推理，结论必须可溯源。**

## 为什么是四角色

单 Agent 分析会在缺少维度支撑时强行归因、放大数值错误。四角色把任务解耦成串行流水线，每环节职责单一，并加入独立复核：

```
① 数据探查 ──► ② 指标统计 ──► ③ 业务洞察 ──► ④ 复核校验 ──► 离线 HTML 报告
   (代码)        (代码)        (LLM+边界)      (代码)
```

## 角色与脚本

| 角色 | 实现 | 脚本 | 产出 |
|---|---|---|---|
| ① 数据探查 | 确定性代码 | `scripts/数据巡检_缺失值与异常值检测.py` | 数据质量报告（缺失/异常/重复） |
| ② 指标统计 | 确定性代码 | `scripts/指标统计_确定性计算.py` | 指标 JSON（数字唯一事实源） |
| ③ 业务洞察 | LLM 子代理 | 由主流程驱动 | 洞察结论（受边界控制） |
| ④ 复核校验 | 代码重算 + 断言 | `scripts/复核校验_代码二次校验.py` | 校验报告（✅/❌） |
| 报告 | 代码 | `scripts/报告生成_离线交互HTML.py` | 离线交互式 HTML |

## 真实性边界控制

业务洞察角色必须遵循归因分级与截断规则（见 `references/真实性边界控制_归因分级与截断规则.md`）：
- **数据足以支撑** → 给出带数字的归因（标注 L1 可验证 / L2 推断）
- **数据不足** → 主动输出「数据不足，无法归因」，禁止编造因果

## 执行流程

1. 运行数据巡检脚本，产出数据质量报告
2. 运行指标统计脚本，产出指标 JSON（数字唯一事实源）
3. 启动业务洞察子代理，输入「指标 JSON + 数据质量报告 + 边界规则」，产出洞察结论
4. 运行复核校验脚本，对核心指标做代码二次校验；并校验洞察归因是否有数据支撑
5. 运行报告生成脚本，合成离线 HTML 报告（含校验结果与可溯源指标明细）
